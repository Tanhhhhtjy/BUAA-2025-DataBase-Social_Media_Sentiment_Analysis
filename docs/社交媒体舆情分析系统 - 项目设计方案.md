# 社交媒体舆情分析系统 - 项目设计方案（最终版）

## 一、项目概述

### 1.1 项目背景

本项目面向社交媒体舆情场景，构建一套基于 **TaurusDB 分布式关系数据库** 的舆情数据管理与分析系统，实现从用户生成内容（UGC）采集、存储，到话题抽取、情感分析、热点分析、关键词预警等全流程功能。

在数据库课设背景下，本系统重点体现：

- 关系数据库建模能力（满足 3NF 的概念/逻辑模式设计）
- 手写 SQL 的复杂查询和性能优化能力
- 利用分布式数据库 TaurusDB 进行高并发数据访问
- 将大模型能力（通过 Spring AI 调用）引入传统数据库应用，实现自动情感分析

### 1.2 建设目标

- 搭建一套支持用户、帖子、评论等数据管理的 Web 系统
- 在 TaurusDB 上实现完整的关系模式、约束和索引
- 使用 MyBatis 手写 SQL 实现所有业务查询与分析逻辑
- 基于 Spring AI 调用大模型完成帖子情感倾向识别（正面/中立/负面）
- 提供热点话题排行、舆情趋势、情感分布和关键词预警等可视化分析能力

### 1.3 总体功能范围

- 用户管理：注册、登录、禁用、删除
- 内容管理：帖子发布、查询、评论管理、级联删除
- 话题管理：话题标签抽取与统计
- 情感分析：帖子情感倾向识别及结果存储
- 热点分析：热点话题排行、舆情趋势、情感分布
- 关键词预警：敏感词配置及近 24 小时预警查询

## 二、总体技术架构

### 2.1 技术选型总览

- 数据库层：TaurusDB（兼容 MySQL 协议/语法的分布式关系数据库）
- 后端服务层：Java 17 + Spring Boot + MyBatis
  - SQL 全部手写（不使用 JPA / 自动 SQL 生成）
  - 使用 Spring AI 调用大模型完成情感分析
- 前端展示层：Vue 3 + Vite + Element Plus + ECharts
- 接口风格：RESTful API，JSON 数据交换

### 2.2 分层架构

系统采用典型的三层架构：

- 表现层（前端）
  - 使用 Vue 3 实现 SPA 单页应用，负责页面展示与交互
  - 通过 Axios 调用后端 REST 接口

- 业务层（后端）
  - 使用 Spring Boot 构建 Web 服务
  - 按模块划分 Controller、Service、Mapper
  - 在 Service 中实现业务流程控制和事务管理
  - 通过 Spring AI 调用外部大模型 API

- 数据层（数据库）
  - 使用 TaurusDB 存储业务数据和分析结果
  - 使用 MyBatis 管理数据访问，所有 SQL 手写
  - 通过主键/外键/唯一约束/索引保证数据完整性与性能

### 2.3 部署架构

- TaurusDB：部署在云端 TaurusDB 集群（课程/云环境提供）
- 后端服务：
  - Spring Boot 应用以可执行 jar 方式部署在云主机或容器中
  - 通过 JDBC 协议连接 TaurusDB
  - 通过 HTTP 调用大模型服务（由 Spring AI 适配）
- 前端应用：
  - 使用 Vite 构建打包后，部署在 Nginx 或由 Spring Boot 静态资源功能托管

整体调用链路：

> 浏览器（Vue） → Spring Boot（业务 + Spring AI） → TaurusDB（数据存储） / 大模型服务（情感分析）

## 三、关键技术栈说明

### 3.1 数据库：TaurusDB

选择 TaurusDB 的原因：

- 与 MySQL 协议兼容，支持现有 MySQL 生态和 SQL 方言
- 提供分布式存储和高可用能力，适合社交媒体场景下的海量数据
- 支持事务、一致性约束、索引和复杂查询，有利于课程中展示数据库设计与优化能力

在本项目中的角色：

- 存储用户、帖子、评论、话题、情感、关键词等核心业务数据
- 利用主键、外键、唯一约束保证数据完整性
- 通过合适的索引提升复杂查询性能（如热点话题、舆情趋势等）
- 部分逻辑可通过触发器/存储过程实现（视 TaurusDB 支持情况而定）

### 3.2 数据访问：MyBatis + 手写 SQL

数据访问层采用 MyBatis，出于课程要求和工程实践的综合考虑，约束如下：

- 不使用 JPA / Hibernate / Spring Data JPA
- 不使用 MyBatis-Plus 的自动 SQL 生成功能
- 所有业务 SQL 通过以下方式手工编写：
  - `Mapper.xml` 中的 `<select>/<insert>/<update>/<delete>` 语句
  - 或 `@Select/@Insert/@Update/@Delete` 注解中的 SQL 字符串

这样设计的目的：

- 符合课程“SQL 必须手写”的硬性要求
- 可以在系统设计报告和演示中重点展示：
  - 建表和约束设计能力
  - 复杂查询（多表联接、分组统计、窗口函数等）的编写能力
  - 针对热点分析、趋势分析等场景的 SQL 优化能力

MyBatis 在项目中的职责：

- 负责 JDBC 连接管理与连接池（基于 HikariCP）
- 负责参数绑定和预编译，防止 SQL 注入
- 负责结果集到实体类的映射（`resultMap` 或自动映射）
- 配合 Spring 事务管理，在 Service 层通过 `@Transactional` 控制事务边界

### 3.3 后端框架：Spring Boot

Spring Boot 作为后端微服务框架，在项目中承担：

- 提供 REST 风格接口：
  - 用户管理接口
  - 帖子/评论 CRUD 接口
  - 舆情分析与热点查询接口
  - 关键词预警接口
- 提供统一的异常处理和响应包装机制
- 提供参数校验能力（如用户名、邮箱、内容长度等）
- 提供日志记录能力，便于调试和运维

安全与认证方面：

- 采用 JWT 作为认证机制
- 登录成功后颁发 JWT，后续请求在 `Authorization: Bearer <token>` 中携带
- 使用 Spring 拦截器或过滤器在网关处统一校验 Token

### 3.4 情感分析：Spring AI + 大模型

本项目将情感分析能力交由大模型完成，后端通过 Spring AI 进行调用，流程如下：

- 在 Spring Boot 中集成 Spring AI，并配置具体大模型提供方
- 定义情感分析服务接口，将帖子文本作为输入
- 设计 Prompt，将任务约束为：
  - 输出帖子情感类别：正面 / 中立 / 负面
  - 输出置信度：0~1 的评分
  - 输出固定 JSON 格式，便于程序解析
- Service 层在处理发帖请求时：
  - 首先将帖子内容写入 `Posts` 表
  - 调用 Spring AI，获取情感分析结果
  - 调用 MyBatis 手写 SQL，将情感结果写入 `Post_Sentiments` 表

考虑到大模型调用的成本和延迟：

- 仅对新发布的帖子进行情感分析
- 可根据需要将情感分析设计为异步任务：
  - 帖子先成功发布
  - 后台异步完成情感分析并更新结果

通过将大模型引入传统数据库应用，本项目体现了“数据库技术 + 大模型技术”的融合创新。

### 3.5 前端技术：Vue 3 + Element Plus + ECharts

前端采用 Vue 3 + Vite 搭建单页应用，结合 Element Plus 和 ECharts 实现管理界面和数据可视化：

- Vue 3：
  - 使用组合式 API 组织页面逻辑
  - 通过 Vue Router 管理多页面路由
  - 通过 Pinia 或轻量状态管理统一存储用户信息和全局状态

- Element Plus：
  - 快速搭建表单、表格、对话框等常用界面
  - 使用分页表格展示帖子和评论列表
  - 使用表单组件实现关键词配置、时间范围筛选等功能

- ECharts：
  - 热点话题排行：柱状/条形图展示话题热度
  - 舆情趋势分析：折线图展示每日正/中/负占比变化
  - 情感分布分析：饼图/环形图展示某时间范围内情感比例

前端与后端通过 Axios 进行 HTTP 通信，统一使用 JSON 格式数据。

## 四、模块设计与数据流

### 4.1 用户与权限模块

- 用户注册：
  - 前端提交注册信息 → 后端校验（用户名、邮箱唯一）→ TaurusDB 插入 `Users` 记录
- 用户登录：
  - 前端提交用户名/邮箱密码 → 后端校验密码哈希 → 生成 JWT 返回前端
- 用户管理：
  - 管理员可以禁用/删除用户
  - 删除用户时，通过外键约束和业务逻辑实现级联删除其帖子和评论

### 4.2 内容管理模块

- 发帖流程：
  - 校验用户状态（已注册且未禁用）
  - 插入 `Posts` 表
  - 调用 Spring AI 获取情感结果，插入 `Post_Sentiments` 表
  - 返回发帖成功响应

- 评论管理：
  - 评论插入 `Comments` 表
  - 根据外键关系关联至对应的帖子和用户

### 4.3 话题与热点分析模块

- 话题抽取：
  - 可以采用以下两种方式之一：
    - 在应用层对帖子内容进行正则/简单 NLP 分析，抽取 `#话题#` 标签并写入 `Hashtags` 与 `Post_Hashtags`
    - 若环境支持，可在 TaurusDB 中通过触发器实现抽取逻辑

- 热点话题查询：
  - 在 TaurusDB 上通过手写 SQL 实现：
    - 统计指定时间范围内每个话题对应的帖子数、评论数
    - 使用权重模型计算热度（例如：热度 = 帖子数 × 0.7 + 评论数 × 0.3）
    - 按热度排序，取前 N 个话题返回

### 4.4 舆情趋势与情感分布模块

- 舆情趋势：
  - 按日期聚合 `Post_Sentiments` 数据
  - 统计每一天正/中/负帖子数量或占比
  - 返回时间序列数据供前端绘制趋势图

- 情感分布：
  - 在指定时间范围内统计各情感类别数量
  - 计算占比，返回给前端绘制饼图

### 4.5 关键词预警模块

- 关键词管理：
  - 管理员在前端页面配置敏感关键词
  - 后端维护 `Keywords` 表，存储关键词和所属类别

- 预警查询：
  - 针对最近 24 小时的帖子和评论
  - 使用 LIKE 或全文索引（视 TaurusDB 支持情况）进行关键词匹配
  - 返回命中记录列表，用于预警展示

## 五、与课程要求的对应关系

### 5.1 数据库设计与范式

- 使用 TaurusDB 存储 8 个核心实体及其关联表
- 概念模型与逻辑模型满足 3NF 要求，避免冗余和异常
- 通过主键、外键和唯一约束实现实体间的严格关联和数据一致性

### 5.2 手写 SQL 与复杂查询

- 所有数据访问 SQL 均由学生手写：
  - 基本 CRUD
  - 多表联接查询
  - 分组统计和排序
  - 热点话题、舆情趋势、情感分布、关键词预警等复杂查询
- 使用 MyBatis 仅作为连接管理、参数绑定和结果映射工具，不依赖自动 SQL 生成功能

### 5.3 数据库高级特性与性能

- 在建表脚本中合理设计索引（如时间、话题、情感等字段）
- 对复杂分析查询进行索引优化与 SQL 调优
- 视环境支持情况使用触发器/存储过程提升部分逻辑的数据库端执行效率

### 5.4 大模型与数据库应用融合

- 通过 Spring AI 引入大模型情感分析能力
- 将大模型分析结果落地到 TaurusDB 中，参与后续统计与可视化查询
- 在系统设计报告中展示大模型调用流程与异常处理机制，体现系统的创新性和工程完整性

## 六、总结

本项目在整体架构上采用“前后端分离 + 分布式关系数据库 + 大模型服务”的设计，在满足课程“数据库建模 + 手写 SQL + 复杂查询”的核心要求基础上，引入 TaurusDB 和大模型技术，使系统在工程实践性和创新性上都具有较强的展示价值。

后续实现阶段将按照本项目设计方案逐步完成：

- 数据库建表、约束和索引实现
- 后端接口开发与 MyBatis SQL 编写
- Spring AI 集成与情感分析逻辑实现
- 前端管理和可视化页面开发
- 测试与性能优化

该设计方案将作为系统具体实现与答辩展示的技术依据。
