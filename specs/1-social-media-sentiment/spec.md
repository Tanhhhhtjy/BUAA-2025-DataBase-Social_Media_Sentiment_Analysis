# Feature Specification: 社交媒体舆情分析系统

**Feature Branch**: `1-social-media-sentiment`
**Created**: 2025-12-15
**Status**: Draft
**Input**: 开发一个社交媒体舆情分析系统，面向数据库课程设计场景，重点展示关系数据库建模和手写 SQL 能力。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用户注册与身份认证 (Priority: P1)

普通用户通过用户名、邮箱和密码完成注册，系统确保用户名和邮箱唯一性。注册后用户可使用用户名或邮箱配合密码登录，获得访问令牌。管理员账号已预置系统。

**Why this priority**: 用户注册和登录是所有功能的基础，是系统的入口点，必须优先实现。

**Independent Test**: 可以通过完整的注册流程测试：访问注册页面 → 输入唯一用户名和邮箱 → 设置密码 → 提交注册 → 使用新账号登录 → 获得访问令牌。整个流程无需其他功能即可独立验证。

**Acceptance Scenarios**:

1. **Given** 系统中有已注册用户A，**When** 新用户尝试使用已存在的用户名注册，**Then** 系统显示"用户名已存在"错误信息，注册失败
2. **Given** 系统中有已注册用户A，**When** 新用户尝试使用已存在的邮箱注册，**Then** 系统显示"邮箱已存在"错误信息，注册失败
3. **Given** 新用户输入有效的用户名、邮箱和密码，**When** 用户提交注册表单，**Then** 系统创建新用户账号，返回成功消息
4. **Given** 已注册用户拥有用户名和邮箱，**When** 用户使用用户名和正确密码登录，**Then** 系统验证成功，返回访问令牌
5. **Given** 已注册用户拥有用户名和邮箱，**When** 用户使用邮箱和正确密码登录，**Then** 系统验证成功，返回访问令牌
6. **Given** 已注册用户，**When** 用户使用错误密码登录，**Then** 系统显示"密码错误"，拒绝访问

---

### User Story 2 - 发布帖子与话题提取 (Priority: P1)

已登录且未被禁用的用户可以发布包含文本内容的帖子。帖子内容支持 #话题名称# 格式的话题标签，系统自动识别并提取话题。发布后自动触发情感分析。

**Why this priority**: 发布内容是社交媒体平台的核心功能，用户发帖后才能进行后续的情感分析和话题追踪。

**Independent Test**: 可以通过发布帖子流程测试：登录 → 输入帖子内容（含话题标签） → 发布 → 查看帖子详情 → 验证话题是否正确提取 → 查看情感分析结果。

**Acceptance Scenarios**:

1. **Given** 用户已登录且账号未被禁用，**When** 用户发布包含文本的帖子，**Then** 帖子创建成功，显示在帖子列表中
2. **Given** 用户发布包含 "#话题1#" 和 "#话题2#" 的帖子，**When** 系统处理帖子，**Then** 自动提取话题1和话题2，建立帖子与话题的关联
3. **Given** 用户发布帖子，**When** 帖子发布成功，**Then** 系统自动调用情感分析服务
4. **Given** 帖子情感分析成功，**When** 查看帖子详情，**Then** 显示情感类别（正面/中立/负面）和置信度评分
5. **Given** 帖子情感分析失败，**When** 查看帖子详情，**Then** 情感结果显示为"未分析"，但帖子内容正常显示

---

### User Story 3 - 评论互动功能 (Priority: P1)

用户可以对帖子发表评论，查看评论列表。评论支持删除操作，用户只能删除自己发布的评论。

**Why this priority**: 评论是用户互动的重要方式，增强用户参与度和平台活跃度。

**Independent Test**: 可以通过完整评论流程测试：查看帖子 → 添加评论 → 查看评论列表 → 编辑或删除自己的评论。无需依赖其他高级功能。

**Acceptance Scenarios**:

1. **Given** 用户查看帖子详情，**When** 用户输入评论内容并提交，**Then** 评论创建成功，显示在评论列表中
2. **Given** 用户查看包含多条评论的帖子，**When** 评论列表加载，**Then** 按时间倒序显示所有评论，显示评论者、时间和内容
3. **Given** 用户查看自己的评论，**When** 用户点击删除按钮，**Then** 评论删除成功，从列表中移除
4. **Given** 用户查看其他用户发布的评论，**When** 用户尝试删除该评论，**Then** 系统拒绝操作，显示"无权删除此评论"

---

### User Story 4 - 帖子浏览与分页 (Priority: P2)

用户可以浏览帖子列表，支持按时间排序和分页。帖子详情页显示完整内容、发布者、发布时间和情感分析结果。

**Why this priority**: 内容浏览是用户消费内容的主要方式，良好的浏览体验对用户留存至关重要。

**Independent Test**: 可以通过浏览流程测试：访问帖子列表 → 查看分页导航 → 点击不同页面 → 查看帖子详情 → 返回列表。验证分页和排序功能。

**Acceptance Scenarios**:

1. **Given** 帖子列表有多页内容，**When** 用户查看第一页，**Then** 显示默认数量的帖子（如10条），显示页码导航
2. **Given** 用户在第1页，**When** 用户点击"下一页"或页码2，**Then** 加载第2页帖子，URL更新，页面滚动到顶部
3. **Given** 用户在最后一页，**When** 用户点击"下一页"，**Then** 按钮禁用或隐藏，提示"已是最后一页"
4. **Given** 用户查看帖子详情，**Then** 显示帖子完整内容、发布者用户名、发布时间、情感分析结果

---

### User Story 5 - 话题管理与浏览 (Priority: P2)

系统自动从帖子中提取话题标签，支持查看所有话题列表和查看特定话题下的所有帖子。

**Why this priority**: 话题功能帮助用户发现相关内容，进行内容聚合和导航。

**Independent Test**: 可以通过话题浏览测试：查看话题列表 → 选择话题 → 查看该话题下的所有帖子。验证话题提取和关联功能。

**Acceptance Scenarios**:

1. **Given** 系统中有已提取的话题，**When** 用户访问话题列表，**Then** 显示所有话题，按帖子数量降序排列
2. **Given** 话题列表中的某个话题，**When** 用户点击话题名称，**Then** 跳转到该话题的帖子列表页，显示所有包含此话题的帖子
3. **Given** 某个话题下没有帖子，**When** 用户访问该话题页面，**Then** 显示"暂无帖子"提示

---

### User Story 6 - 情感分析与存储 (Priority: P2)

每条帖子发布后自动进行情感分析，结果包括情感类别（正面/中立/负面）和置信度评分（0-1），持久化存储供后续查询。

**Why this priority**: 情感分析是舆情分析系统的核心功能，为后续的趋势分析和预警提供数据基础。

**Independent Test**: 可以通过情感分析流程测试：发布帖子 → 等待分析完成 → 查看帖子详情中的情感结果 → 执行情感分布查询。验证分析结果存储和查询功能。

**Acceptance Scenarios**:

1. **Given** 帖子发布完成，**When** 情感分析服务处理帖子，**Then** 生成情感类别和置信度评分，保存到数据库
2. **Given** 多个帖子有不同的情感结果，**When** 执行情感分布查询，**Then** 返回正面、中立、负面帖子的数量和占比
3. **Given** 情感分析失败，**When** 系统重试后仍失败，**Then** 标记情感结果为"未分析"，不阻塞帖子发布

---

### User Story 7 - 热点话题排行榜 (Priority: P2)

查询指定时间范围内的热点话题排行榜，按热度值排序。热度计算：帖子数 × 0.7 + 评论数 × 0.3。

**Why this priority**: 热点排行帮助用户了解当前热门话题，提供内容推荐和趋势洞察。

**Independent Test**: 可以通过热点查询测试：设置时间范围 → 查询热点排行榜 → 验证热度计算结果。验证排序和热度算法。

**Acceptance Scenarios**:

1. **Given** 系统中有多条帖子和评论，**When** 查询最近7天的热点话题，**Then** 返回前N个话题（默认10），按热度降序排列
2. **Given** 话题A有10个帖子和50个评论，**When** 计算热度值，**Then** 热度 = 10 × 0.7 + 50 × 0.3 = 22
3. **Given** 查询结果，**Then** 每个话题显示：话题名称、帖子数、评论数、热度值

---

### User Story 8 - 舆情趋势分析 (Priority: P3)

查询指定时间范围内的每日舆情趋势，返回每天正面、中立、负面帖子数量，用于前端绘制趋势折线图。

**Why this priority**: 趋势分析提供舆情走向的宏观视角，帮助管理员了解情感变化趋势。

**Independent Test**: 可以通过趋势查询测试：设置时间范围 → 查询舆情趋势 → 验证每日数据统计 → 绘制趋势图。验证时间序列数据聚合。

**Acceptance Scenarios**:

1. **Given** 系统中有多天的帖子数据，**When** 查询最近30天的舆情趋势，**Then** 返回每天的统计：日期、正面帖子数、中立帖子数、负面帖子数
2. **Given** 某天没有帖子，**Then** 该日期的统计显示为0，不跳过日期
3. **Given** 趋势查询结果，**Then** 数据按日期升序排列，可直接用于折线图绘制

---

### User Story 9 - 情感分布统计 (Priority: P3)

查询指定时间范围内的情感分布统计，返回正面、中立、负面帖子的数量和占比，用于前端绘制饼图。

**Why this priority**: 情感分布提供舆情的总体情感倾向概览，帮助快速了解整体舆论态势。

**Independent Test**: 可以通过分布查询测试：设置时间范围 → 查询情感分布 → 验证数量和占比计算 → 绘制饼图。验证百分比计算准确性。

**Acceptance Scenarios**:

1. **Given** 系统中有多条帖子，**When** 查询最近30天的情感分布，**Then** 返回三种情感类别的数量和占比（如正面：30篇(50%)、中立：18篇(30%)、负面：12篇(20%)）
2. **Given** 查询结果，**Then** 所有占比相加等于100%
3. **Given** 情感分布查询，**Then** 数据可直接用于饼图绘制

---

### User Story 10 - 管理员用户管理 (Priority: P3)

管理员可以查看所有用户列表（支持分页）、禁用或启用用户账号、删除用户。删除用户时级联删除该用户的所有帖子和评论。

**Why this priority**: 用户管理是管理员的核心职责，确保平台内容质量和用户行为规范。

**Independent Test**: 可以通过用户管理流程测试：管理员登录 → 查看用户列表 → 禁用/启用用户 → 删除用户 → 验证级联删除。验证权限控制和级联操作。

**Acceptance Scenarios**:

1. **Given** 管理员已登录，**When** 查看用户列表，**Then** 显示所有用户，支持分页，显示用户名、邮箱、状态（正常/禁用）、注册时间
2. **Given** 管理员选择正常状态的用户，**When** 点击"禁用"按钮，**Then** 用户状态更新为禁用，该用户无法登录和发布内容
3. **Given** 管理员选择禁用状态的用户，**When** 点击"启用"按钮，**Then** 用户状态更新为正常，用户可正常登录
4. **Given** 管理员选择用户，**When** 点击"删除"按钮并确认，**Then** 删除该用户及其所有帖子和评论

---

### User Story 11 - 关键词预警管理 (Priority: P3)

管理员可以配置敏感关键词（包括内容和类别），查看、编辑、删除关键词，查询最近24小时内命中敏感关键词的帖子和评论。

**Why this priority**: 关键词预警帮助管理员及时发现和处理敏感内容，维护平台内容安全。

**Independent Test**: 可以通过预警管理测试：配置关键词 → 发布包含关键词的帖子 → 查看预警列表 → 验证预警信息显示。验证关键词匹配和预警功能。

**Acceptance Scenarios**:

1. **Given** 管理员登录系统，**When** 添加敏感关键词（如"政治敏感"类别），**Then** 关键词保存成功，显示在关键词列表中
2. **Given** 系统中已配置敏感关键词，**When** 发布包含关键词的帖子，**Then** 系统标记该内容，自动生成预警记录
3. **Given** 管理员查看预警列表，**Then** 显示内容类型（帖子/评论）、内容摘要、命中的关键词、类别、发布时间、发布者
4. **Given** 管理员编辑已有关键词，**When** 修改关键词内容或类别，**Then** 更新成功，新的匹配规则立即生效

---

### Edge Cases

- 用户发布空内容或仅包含话题标签的帖子
- 同时有多个用户发布帖子时的话题提取
- 情感分析服务不可用时的处理（标记为"未分析"）
- 分页查询时数据被删除或修改
- 热点话题计算时时间范围内的数据为空
- 用户删除后相关数据的完整性保证
- 关键词预警中中文字符匹配（不区分大小写的精确匹配）
- 并发访问时的数据一致性
- JWT 访问令牌过期后的处理（需要重新登录）
- 管理员账号被禁用的异常情况处理
- 触发器执行失败时的回滚机制

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持用户注册，确保用户名和邮箱唯一性
- **FR-002**: 系统 MUST 支持用户登录，验证用户名/邮箱和密码，返回访问令牌
- **FR-003**: 系统 MUST 允许已登录且未禁用的用户发布帖子
- **FR-004**: 系统 MUST 自动识别并提取帖子中的 #话题# 格式标签，建立话题关联
- **FR-005**: 系统 MUST 为每条帖子自动调用情感分析，存储情感类别和置信度
- **FR-006**: 系统 MUST 支持用户对帖子发表评论
- **FR-007**: 系统 MUST 支持帖子列表浏览，按时间排序，支持分页
- **FR-008**: 系统 MUST 提供话题列表浏览和话题下帖子列表功能
- **FR-009**: 系统 MUST 支持热点话题排行榜查询，按指定公式计算热度
- **FR-010**: 系统 MUST 支持舆情趋势查询，按日期聚合情感分布数据
- **FR-011**: 系统 MUST 支持情感分布统计查询，返回数量和占比
- **FR-012**: 系统 MUST 支持管理员用户管理：查看、禁用/启用、删除用户
- **FR-013**: 系统 MUST 支持管理员关键词管理：添加、编辑、删除敏感关键词
- **FR-014**: 系统 MUST 自动检测命中敏感关键词的内容，生成预警记录
- **FR-015**: 系统 MUST 在用户删除时级联删除相关帖子和评论
- **FR-016**: 系统 MUST 在帖子删除时级联删除相关评论
- **FR-017**: 系统 MUST 预置一个管理员账号供系统初始化使用
- **FR-018**: 系统 MUST 确保被禁用用户无法登录和发布内容

### Key Entities

- **用户 (User)**: 系统用户，包含用户名、邮箱、密码哈希、角色（普通/管理员）、状态（正常/禁用）。注：系统仅包含两种角色：普通用户和系统管理员
- **帖子 (Post)**: 用户发布的内容，包含文本内容、发布时间、发布者、情感分析结果
- **评论 (Comment)**: 用户对帖子的回复，包含文本内容、发布时间、评论者、关联帖子
- **话题 (Hashtag)**: 从帖子中提取的话题标签，包含话题名称、创建时间。注：话题在帖子发布时同步提取并存储
- **帖子话题关联 (PostHashtag)**: 帖子和话题的多对多关联关系
- **情感分析 (SentimentAnalysis)**: 帖子的情感分析结果，包含情感类别、置信度、分析时间。注：通过数据库触发器异步调用存储过程实现
- **敏感关键词 (SensitiveKeyword)**: 管理员配置的关键词，包含关键词内容、类别、创建时间。注：匹配规则为精确匹配，不区分大小写
- **预警记录 (Alert)**: 命中敏感关键词的内容记录，包含内容类型、内容摘要、关键词、类别、时间

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可以在 30 秒内完成注册流程，获得有效的访问令牌
- **SC-002**: 用户发布帖子后，话题提取在 5 秒内完成并显示在话题列表中
- **SC-003**: 情感分析在帖子发布后 10 秒内完成，99% 的帖子获得情感标签
- **SC-004**: 帖子列表分页加载时间不超过 2 秒，支持流畅的翻页操作
- **SC-005**: 热点话题排行榜查询响应时间不超过 3 秒，热门数据实时更新
- **SC-006**: 舆情趋势查询返回最近 30 天的完整数据，数据准确率 100%
- **SC-007**: 管理员可以管理用户账号，禁用/启用操作在 1 秒内生效
- **SC-008**: 关键词预警在内容发布后 5 秒内生成预警记录
- **SC-009**: 系统支持 1000 个并发用户同时浏览帖子，无明显性能下降
- **SC-010**: 数据完整性保证：删除用户时 100% 级联删除相关帖子和评论

## Assumptions

- 使用华为云 GaussDB(for MySQL) 作为数据库管理系统
- 大模型情感分析服务通过触发器异步调用存储过程实现（数据库层处理）
- 用户访问令牌使用 JWT 格式，有效期 24 小时
- 前端支持可视化图表展示（折线图、饼图）
- 系统面向数据库课程设计，重点展示关系建模和手写 SQL
- 默认分页大小为 10 条记录
- 默认热点排行榜显示前 10 个话题
- 情感类别固定为：正面、中立、负面
- 置信度评分范围：0-1
- 话题发布时同步提取，存储到话题表
- 敏感关键词匹配采用精确匹配，不区分大小写

## Dependencies

- 华为云 IAM 身份认证服务
- 华为云 DAS 数据库管理服务
- 大模型情感分析 API
- JWT 令牌管理
- 数据库触发器和存储过程
